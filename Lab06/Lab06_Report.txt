1. FIFO vs LRU (Phase 2)

The LRU algorithm performed better than FIFO because it remembers which page was used most recently. When the memory is full, LRU removes the page that has not been used for the longest time. This helps keep frequently used pages in memory and reduces page faults.

FIFO only removes the oldest page in memory. It does not consider whether the page is still being used, so it may remove a page that the program needs again soon. Therefore, FIFO usually has more page faults than LRU.

------------------------------------------------------

2. Understanding Thrashing (Phase 3)

Thrashing happens when the operating system spends most of its time moving pages between RAM and disk instead of running the program.

In Scenario 2, the processing time is much higher because the system keeps reading and writing data to the disk. Disk access is much slower than RAM, so the CPU has to wait, making the whole program run much slower.

------------------------------------------------------

3. AI Engineering Decision

Lowering the batch_size reduces the amount of memory needed during AI model training. When the memory usage becomes smaller, the data can fit into RAM without using swap space.

As a result, the operating system does not need to move pages between RAM and disk frequently. This prevents thrashing, reduces page faults, and makes the AI model run faster and more efficiently.
