1. Disk Scheduling (Phase 2)

In my run of disk_scheduler.py, the head starts at track 53 and the
requests are [98, 183, 37, 122, 14, 124, 65, 67]. FCFS had a total
head movement of 640 cylinders and SCAN had 331 cylinders, so SCAN
moved about half as much.

FCFS serves the requests in the order they arrive, so the head jumps
back and forth (53 -> 98 -> 183 -> 37 -> 122 -> 14 -> ...). For
example, it goes from 183 down to 37 and later from 14 up to 124.

SCAN works like an elevator. It sorts the requests, moves the head in
one direction (up) and serves every request on the way: 65, 67, 98,
122, 124, 183. Then it goes to the end of the disk (199), reverses,
and serves the remaining requests (37, 14) on the way down. Each part
of the disk is passed only once or twice, so the total movement is
much smaller.

2. I/O Bound Concept

If a system is "I/O Bound", the process spends most of its time
waiting for the disk (or other I/O device) instead of calculating.
The CPU is mostly idle, not at 100% usage. The process is in the I/O
wait state, so the CPU has no work to do for it until the data
arrives. The speed of the whole task is limited by the disk, not by
the CPU.

3. AI Industry Connection (Phase 3)

In my run of ai_dataset_io.py, reading 1000 separate small files took
0.0252 seconds and reading one packed file took 0.0006 seconds. Both
read the same number of bytes, but the packed file was about 42 times
faster in this run. (The exact ratio changes from run to run because
the packed test is very short, but it was always much faster.)

With separate files, the OS must open, find the inode, check the
permissions, read, and close the file again for every file. With
1,000,000 .jpg files, this overhead is repeated 1,000,000 times, and
the disk may have to jump to different places (random I/O). The GPU
finishes its calculation quickly and then waits for the next batch of
images, so its usage drops. This is called GPU starvation.

A packed format such as TFRecord, WebDataset, or HDF5 opens the file
once and reads large continuous blocks (sequential I/O). The disk can
send data fast and steadily, so the GPU stays busy.
